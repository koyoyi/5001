# TechQA 第二轮检索与学习重排实验协议

本轮检验轻量监督重排在强检索与融合基线之外是否仍有价值。开发阶段比较固定的输入、检索和训练条件；保留集只评价预先固定的主方案。结果可以是没有稳定增益，不以取得正向分数作为停止条件。

## 1. 队列与分区

数据采用本地已核验的 NVIDIA TechQA 固定快照，合并完全相同的文档正文后有 28,478 篇文档。原有 581 个有已知 gold 的规范查询，先按共享 gold 和字符近重复连接成组件。

第二轮由 Codex 助手使用完整问题文本、原文证据和冻结 BGE 的问题间相似度逐对审阅，未读取测试检索指标；实际成员或领域专家尚未独立核验这些语义判读。依照明确的问题／产品／错误机制规则，助手将 `TRAIN_Q007、TRAIN_Q272、TRAIN_Q450` 判为同一升级后 MQ 用户身份／2035 授权问题，原本跨训练与测试。该组件整体隔离，保留 578 个查询：训练 410、开发 84、保留测试 84；分别属于 336、72、72 个组件。

[历史分区锁](../configs/techqa_split_lock.json)保存全部原始分区。新组件跨越旧分区时整体隔离，其余查询保留原分区；没有把看过的训练或开发样本重新随机分进测试。原始分区清单 SHA-256 为 `8094c45eeb5468678350fb283a5face880cccd1a3b8f82478373bcce0d6e8e35`。

筛查产生 989 对候选。定界审查的 89 对高风险跨区候选中，81 对请求不同 CVE，5 对产品或公告周期不同，1 对为上述 MQ 问题，2 对仍有源 CVE 与 gold 不一致的标注疑点。低相似候选未被穷尽人工审查，不能据此声称零语义泄漏。SPSS Mac 启动卡住的两个问题具有相近症状但不同已知修复原因，记录为敏感性风险，没有直接当成同根因合并。完整证据见 [group_review](../results/group_review/)。

## 2. 有限的主要管线

| 管线 | 文档输入 | 语义检索 | 作用 |
| --- | --- | --- | --- |
| head LSA | 每篇前 256 个空白分隔词 | TF-IDF／128 维 LSA | 与首轮衔接的轻量基线 |
| full LSA | 完整原文 | TF-IDF／128 维 LSA | 长文输入的受控对照 |
| head BGE | 每篇前 256 个空白分隔词 | 冻结 BGE small、512 WordPiece 上限 | 事先指定的神经检索主方案 |

BGE 使用固定 revision 的官方 FP32 ONNX 导出、CLS 池化、L2 归一化和精确 cosine 搜索。Query 使用固定英文检索指令，文档无指令。小样本数值对照通过后端等价阈值；没有用动态 int8 替代 FP32。每批向量按模型、文本顺序、Tokenizer、指令、精度与参数生成身份并校验落盘，允许中断恢复。缓存读取、历史编码和本次新编码耗时分别记录。

每个查询由 BM25 和语义检索各提供 top100，按原始文档 ID 得到完整候选并集。BM25 零分不作为命中。RRF、加权 RRF、Logistic 与 RF 排序同一并集，不补入 gold，不先用 RRF 截断。加权 RRF 的语义权重在开发集从 `0、0.25、0.5、1、2` 选择，包含 BM25-only 端点，以检验学习增益是否只是恢复强词项基线。

## 3. 拟合、验证与训练对照

主模型使用原来的九个检索／名次／缺榜／词项覆盖／长度特征。L2 Logistic 的 C 在 `0.1、1、10` 中选择；RF 固定 200 棵树，深度在 `6、12`、叶节点最少行数在 `10、30` 中选择。三折 CV 按组件分组，标准化只在训练折拟合。拟合使用训练候选内已召回正例和至多 50 个未标注代理负例；未召回正例的查询不进入监督拟合，但保留在整个评价队列。

神经主方案每个可拟合查询的样本总权重固定为 51，与默认一正五十负的预算一致。改变负例数量时仍保持相同预算，避免在固定 C 的对照里同时改变有效正则化。正负例默认不做类别平衡，输出只用作排序分数。

以下六个对照逐个改变训练因素，复用主方案的完整候选、原始特征和训练 CV 选定参数，不再调参：

1. 随机代理负例上限 10。
2. BM25 高分困难代理负例，上限 50。
3. 每个查询正、负两类各分配一半权重。
4. 负采样／训练种子 20261115。
5. 负采样／训练种子 20261116。
6. 只使用两个倒数名次与两个缺榜标记。

代理负例不等于人工确认不相关；困难负例尤其可能包含未标注相关文档。对照用于解释稳定性，不预设哪一种应当获胜。各折的拟合／验证查询与组件数、漏正例数、配对行数和权重由 [audit_cv_support.py](../scripts/audit_cv_support.py)另行核对。

## 4. 评价与一次性保留集

主指标为 query 宏平均 nDCG@10，次指标为 Recall@20。候选召回用于区分召回瓶颈与重排损失。当前每个查询只有一篇已知 gold，Recall@20 也是该文档的 hit@20，不代表穷尽证据召回。

所有学习模型分别与 BM25、普通 RRF、加权 RRF 做组件级配对 bootstrap，报告差值和 95% 百分位区间。开发集参与选择，因此这些区间是探索证据，多项对照不能被当作独立的确认性显著性结论。

在神经主方案开发成绩出现之前，[保留集协议](../configs/iteration2/heldout_protocol.json)已指定：**head BGE 的默认 Logistic 与加权 RRF，在 nDCG@10 上作主要比较**。六个训练对照只作开发阶段稳健性分析，不按其开发最大值更换主要比较。RF、其他检索方法与 Recall@20 为次要结果。

主方案完成、独立核验后，冻结其模型、特征、候选、RRF 选择、分区、代码与协议哈希，再对保留测试评价一次。技术性写入失败只允许在完全相同的冻结身份下恢复，原训练／开发结果和模型保持不变。测试结果无论正负均报告，之后不再据该测试分数调参；进一步方法选择需要新的独立评价。

## 5. 延迟与生成案例

在线延迟在主要离线任务停止后，使用固定开发查询、预热、串行重复和明确线程设置测量。计时包括 query 编码、检索、必要特征、重排与输出 top-k；排除下载、模型加载与离线文档编码。RRF 不计算它不需要的学习特征。并发编码期间的单次耗时不能作为稳态服务延迟。

生成层使用独立的冻结本地小模型，展示实际检索证据、引用映射、固定 prompt、截断预算和原始输出。不会把参考答案送入 prompt，也不会补引用后声称模型生成正确。自动检查仅覆盖引用是否合法和证据是否缺失；助手逐例审阅须明确其 AI 辅助性质，不能冒充真实成员的独立人工评审。生成案例不构成问答准确率实验，也不改变上述训练或测试选择。

## 6. 结果解释的边界

本研究是自定义技术支持档案上的域内监督检索，不是官方 TechQA 大规模测试，也不是生成答案正确性基准。给定 qrels 存在稀疏性和已知源标注疑点；head 输入会丢失长文尾部信息；近重复审查仍有覆盖限制。完整原文对照、强基线、有限稳健性实验与保留集评价用于界定这些结论，不用于证明模型已经达到最优。
