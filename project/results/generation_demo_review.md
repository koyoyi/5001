# 本地生成演示的结果与限制

冻结 Qwen2.5 0.5B Instruct 在五个固定开发案例上运行了两阶段演示：先生成回答内容，再由同一模型提出支持来源标签。两个原始输出分别保存，引用来源明确为第二次模型调用，没有把补充标签冒充第一次模型输出。

这是定性演示，不是问答准确率基准。模型和提示词只在自拟的备份保留期、端口及缺证据控制上确定，未用数据集参考答案调提示词；真实五例产生后没有重新调参或重跑挑选。

## 实际输出

| 开发问题 | 内容输出 | 引用输出 | 结果 |
| --- | --- | --- | --- |
| TRAIN_Q049 | `D3` | `[D3]` | 只有标识，没有答案，内容失败；问题本身混用两个 CVE 编号 |
| DEV_Q010 | `Insufficient evidence.` | 跳过 | 拒答；长问题被截断，未形成有效解决方案 |
| DEV_Q014 | 从 WebSphere V8 开始改变更新方式 | `[D1]` | 所见 D1 支持 V8 的版本边界，措辞仍需审阅 |
| DEV_Q035 | `Insufficient evidence.` | 跳过 | 拒答；已见相关漏洞描述，存在过度保守的可能 |
| DEV_Q046 | `Insufficient evidence.` | 跳过 | 拒答；所见证据解释了删除限制，模型仍未形成回答 |

查询 ID 的 TRAIN／DEV 前缀来自原档案，以上五例在本实验锁定分区中全部属于开发集。没有生成保留测试问题。

DEV_Q014 的 `[D1]` 对应 `swg21427178.txt`。模型所见文本明确说明 WebSphere V8 及以上将 JDK 与应用服务器更新合为同一包，而 V7 及以下使用 UpdateInstaller，支持回答中的主要版本边界。该判断由 Codex 助手对实际 prompt 片段作 AI 辅助审阅，实际成员或领域专家尚未独立核验。

## 可追溯性

只从已经检索返回的文档 ID 读取原始语料全文，按固定规则截取单一连续原文窗口；没有补入未检索到的 gold，也没有把 QA 参考答案放进 prompt。原始检索文档头、窗口字符偏移、实际进入模型的片段及两阶段 prompt／token／哈希均保留。15 个来源窗口已逐一核对，全部等于原文对应的字符子串。

所有第一阶段输入均不超过 512 token；部分长问题和证据因此被截断。问句末尾的关键约束可能丢失，不能只凭检索命中就判定生成条件充分。

## 当前边界

小型本地生成器尚不可靠。合法引用只证明标签来自提供的来源集合，不能证明语义受支持、回答针对问题或操作建议适用。当前证据支持继续改进问题与证据预算、生成器能力和独立语义评审；不能宣传为可靠技术支持问答系统。这些生成结果不改变已经冻结的检索／重排结论。
