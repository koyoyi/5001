# SDSC5001：已知研究方向、推理性能与 RAG 的选择

调研日期：2026-11-07。依据论文原文、会议页面与官方项目文档。本文是选题评估，RAG 尚是新提出的候选；没有更换已写好的推理服务 Proposal，也没有开始模型下载或实验。

## 1. 判断

**两个方向都成立，但练到的技术不同。**

| 目标 | LLM 推理性能建模 | RAG 检索与重排 |
|---|---|---|
| 主要技术 | 请求并发、排队、计时、推理后端、GPU 运行与性能验证 | 倒排／向量检索、候选融合、重排、API、数据与评测 |
| 5001 自己训练什么 | 延迟／goodput 的统计预测模型 | 相关性排序模型，或查询路由／校准模型 |
| 可展示的成品 | 压测与性能分析工具、配置推荐 | 可搜索、显示证据并生成引用回答的应用 |
| 主要依赖 | 本机后端兼容性、稳定的尾延迟测量 | 有相关性标注的数据、可靠的训练／测试分离 |
| 主要风险 | 三个配置可能穷举就够；小模型可能缺少明显性能取舍 | 只有组件调用时研究内容偏少；检索分数不代表回答正确 |
| 更接近的工作 | AI 基础设施、运行时、服务性能工程 | 搜索／推荐相关工程、AI 应用、后端与知识系统 |

这是技术内容与作品形态的判断，不是岗位数量、薪资或录用概率的市场统计。

**若希望较快做成完整应用，同时保留清楚的统计学习实验，我更倾向 RAG 的检索与学习型重排。若重点是 GPU／运行时／系统性能，则保留推理性能方向。**

## 2. 已知的推理性能方向

### 2.1 性能预测与部署选择：Vidur

[Vidur，MLSys 2024 论文](https://proceedings.mlsys.org/paper_files/paper/2024/file/b74a8de47d2b3c928360e0a011f48351-Paper-Conference.pdf) 结合算子实测、预测模型与离散事件模拟，评估工作负载和配置下的推理性能；Vidur-Search 再按性能约束寻找部署配置。[官方代码](https://github.com/microsoft/vidur)

它为“性能预测→配置决策”提供直接先例。但原方案的 run 级统计预测不是算子模拟器复现，不能借用原文的精度或节省成本数字作为自己的成绩。

### 2.2 计算／访存机理与回归结合

[Predicting LLM Inference Latency: A Roofline-Driven ML Method](https://mlforsystems.org/assets/papers/neurips2024/paper28.pdf) 是 NeurIPS 2024 的 Machine Learning for Systems Workshop 工作，结合 roofline 分析与回归捕捉运行开销；不是 NeurIPS 主会论文。

[GenZ 的作者论文，2025 v3](https://arxiv.org/html/2406.01698v3) 则以解析建模探索计算、内存和通信特征对推理性能的影响。解析估计、模拟输出和实际服务的排队尾延迟是不同证据，不能互相当作独立真值。

### 2.3 吞吐与延迟的调度取舍

[Sarathi-Serve，OSDI 2024](https://www.usenix.org/conference/osdi24/presentation/agrawal) 研究 prefill 与 decode 干扰，采用分块 prefill 和相应调度平衡吞吐与延迟。

[DistServe，OSDI 2024](https://www.usenix.org/conference/osdi24/presentation/zhong-yinmin) 将 prefill、decode 分配到不同 GPU；[Llumnix，OSDI 2024](https://www.usenix.org/conference/osdi24/presentation/sun-biao) 涉及多实例运行时重调度和迁移。它们可作背景，单卡三周课程项目不宜承诺完整复现。

### 2.4 测量与配置扫描已有成熟工具

[GuideLLM](https://vllm-project.github.io/guidellm/stable/getting-started/benchmark/) 已提供多种到达模式及负载扫描；[vLLM 的参数扫描工具](https://docs.vllm.ai/en/stable/benchmarking/sweeps/) 支持配置探索。因此，自写压测器有工程学习价值，但不能仅凭它宣称提出新研究方法。

### 对原方案的修正建议

- 除常数基线，还应比较训练期最佳固定配置、查表／简单插值等强基线。
- 仅有 slots=1/2/4 时，新负载上试完三个配置可能很便宜；必须讨论预测模型是否值得使用。
- 测试优先增加“完整工作负载留出”：同一输入分布和到达模式的全部配置、重复运行一同留出，而非只随机留出几个组合。
- 小试检查不同负载下是否真的存在配置取舍。若某个配置始终最好，可研究拥塞、容量边界和预测失效，不强造推荐优势。
- 独立 run 数量与 p95 稳定性优先于模型复杂度。

这些建议仍需小试证据支持，并不是已经观察到的实验结果。

## 3. RAG 的已知研究路线

### 3.1 检索与重排：最适合起步

官方 [Sentence Transformers Retrieve & Re-Rank](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html) 展示先检索候选、再用较昂贵模型精排的结构。[BEIR](https://github.com/beir-cellar/beir) 提供多种检索任务、相关性标注和统一评价工具。

课程项目可以研究：关键词与语义检索是否互补，学习到的融合／重排能否超过固定融合，提升是否值得额外延迟。

这条路线同时包含信息检索、模型比较、API 和数据管线。预训练 embedding／reranker 是组件；课程中自己训练的轻量排序模型才构成明确的统计学习部分。

### 3.2 自适应选择：什么时候值得增加检索成本

[Adaptive-RAG，NAACL 2024](https://aclanthology.org/2024.naacl-long.389/) 根据问题复杂度，用分类器选择不同检索／生成策略。它说明查询路由已有明确研究先例。

可以缩小为：“哪些查询值得调用 reranker？”以检索前后质量变化构建训练标签，用 Logistic／RF 预测是否调用。其范围小于原论文的策略体系，不称为完整复现。

### 3.3 评价与可信度

[ARES，NAACL 2024](https://aclanthology.org/2024.naacl-long.20/) 区分上下文相关性、答案忠实性和答案相关性，并利用人工标注校正自动评价误差。

因此，不能把另一个 LLM 打出的高分当作唯一正确性证明。检索命中、答案由证据支持、答案本身正确，是不同评价对象。

## 4. 建议的 RAG 课题

**中文：面向 RAG 的混合检索与学习型重排序——效果与延迟的实证研究。**

**English: Can Learned Reranking Improve Hybrid Retrieval for RAG at an Acceptable Latency Cost?**

### 研究问题

1. BM25、向量检索和固定融合各自在哪些查询上表现更好？
2. 基于两类检索特征训练的轻量重排模型，能否在未见查询上改善排名？
3. 增益是否足以支持额外计算成本？效果退步的查询有什么共同特征？

### 最小方法阶梯

1. BM25 关键词检索。
2. 固定的预训练向量检索。
3. 固定 RRF 融合；融合规则及候选数在开发集确定。
4. Logistic 相关性模型，将 BM25／向量分数、各自名次、词项重合等特征转为排序分数。
5. 小型 RF 作非线性比较；预训练 cross-encoder 重排可作额外参照。

各方法必须区分第一阶段召回与第二阶段重排效果。若相关文档根本没进入候选集，重排无法凭空找回它。对同一固定候选集比较重排器，并额外报告候选召回上限。

不默认把 BM25 和向量原始分数直接相加，因为量纲不同。归一化与学习参数只在训练／开发数据拟合。

### 数据与验证

可以先用 [BEIR SciFact](https://huggingface.co/datasets/BeIR/scifact)：公开页面列出 5,183 篇文档，原始任务是科学主张的证据检索；提供训练与测试相关性标注，标准测试含 300 条查询。数据表中的 query-document 标注行数不等于独立查询数。

若希望更多查询及业务文本，可考虑 [BEIR FiQA](https://huggingface.co/datasets/BeIR/fiqa)，提供 train/dev/test。正式选用前再核实实际文件、各分区独立 query 数、来源与许可。

- 遵循已有测试划分；没有开发集时只在训练查询中划出开发集。
- 同一 query 的所有候选文档必须处于同一折；近重复问题也要检查。
- 训练候选和负采样规则只使用训练资料。未标注文档不等于已证明不相关，应说明标注不完备的影响。
- 如果在同域训练轻量模型，报告“域内监督实验”，不冒充 BEIR 标准零样本成绩。
- 主指标 nDCG@10、Recall@20，补充检索／重排延迟、吞吐和资源开销；按 query 做配对比较和不确定性估计。
- 延迟测试固定硬件与缓存条件，区分在线查询延迟和离线建立索引时间。

### 演示层如何接入生成

应用流程：

~~~text
文档 → 清洗与索引 → BM25／向量候选 → 融合／学习重排
                                        ↓
                              文档证据、ID和引用位置
                                        ↓
                              固定LLM生成带引用回答
~~~

固定生成模型与 prompt，先证明检索层的作用。BEIR 的相关性标注主要评价检索，不能直接充当所有生成回答的标准答案。生成层可展示证据与引用，并做透明的小样本人工核对；若缺少回答级标注，不宣称已经证明整体问答准确率提升。

## 5. 更进一步的统计学习题

完成基础检索实验后，最多选一项：

- **查询路由**：预测 reranker 是否值得调用，对比永不调用、始终调用、规则路由，以及相同调用预算的随机选择。特征只能来自调用前。
- **检索成功概率校准**：预测 top-k 是否包含已标注相关证据，报告 Brier、校准和覆盖率。这不是答案真实性概率。

不要同时加入多跳、图谱、复杂 agent 和大模型微调。三周内先把数据、基线、训练、验证和一个可演示应用做扎实。
